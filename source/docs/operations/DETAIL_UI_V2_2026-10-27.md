# Danh sách chi tiết — UI V2 (27/10/2026)

## Scope
UI-only, use checkpoint `checkpoint/pre-ui-2026-10-27`. Firebase primary, rules, imported rows, PR #83 guest publication and Supabase are excluded.

## Dashboard before table
Exactly 3 cards:
- Tiến độ xin ý kiến Thành ủy: Sở chưa trình → VP đang thực hiện → Bước tiếp theo (sum of Đã gửi ĐU + ĐU đã gửi TU, chưa họp + Đã họp/xin phiếu, chưa có TBKL) → Đã có TBKL.
- Tiến độ trình xây dựng NQ: Sở chưa trình → VP đang thực hiện → Đã trình HĐND, chưa có QĐ (one status) → Đã có QĐ chấp thuận.
- Tiến độ trình ban hành NQ: Sở chưa trình → VP đang thực hiện → Đã trình HĐND TP; source scope includes NQ and BC consistent with existing council report.

Each card: exact report totals, completion count and percent, segmented bar ordered left to right exactly as stages (segment size proportional to case count); accessible segment totals; clickable stage counts to drill into records. Intermediate stages use light muted tone; source red, office amber, completed green. Unknown statuses must not be silently classified or counted as complete.

## Compact list
Six displayed columns in four visual groups:
1. Hồ sơ: `displayCode` (NQ01/BC01), then `type` badge, department and content within second cell.
2. Trách nhiệm: UBND leader, VP leader, specialist name abbreviated; room in parentheses after specialist. No duplicated department.
3. Chuỗi tiến độ: Thành ủy (partyLevel) + progressParty, Xây dựng NQ + progressBuild, Ban hành NQ + progressCouncil. Preserve exact underlying values.
4. Theo dõi: specificProgress and note remain distinct columns.

Compact is default. The user can switch to the **existing** full-column table, retain per-column show/hide/filter/reorder/resize and all cell edits by record and field. A source column is never deleted or merged in persisted records; the compact table is a display projection. Permissions apply to individual fields, not visual columns.
